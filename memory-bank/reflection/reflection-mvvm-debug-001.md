## ⚠️ 遇到的挑战

### 1. 类型兼容性问题

**挑战**：
- 在集成调试钩子时，遇到了 `Watcher` 类型的不一致问题
- `IWatcher` 接口和 `Watcher` 类的类型定义需要统一

**解决方案**：
- 统一使用 `Watcher` 类而不是接口
- 更新 `IReactive` 接口以使用 `Watcher` 类
- 确保类型定义的一致性

**经验教训**：
- 类型定义需要保持一致性
- 接口和类的选择需要明确
- 类型兼容性测试很重要

### 2. 性能监控的时机

**挑战**：
- 性能监控需要在关键路径添加，但不能影响性能
- 需要区分调试模式和性能监控模式

**解决方案**：
- 使用条件检查，只在启用时记录
- 使用 `performance.now()` 高精度计时
- 分离性能监控和调试功能

**经验教训**：
- 性能监控本身不能成为性能瓶颈
- 需要仔细选择监控点
- 条件检查是必要的

### 3. 依赖关系图构建

**挑战**：
- 路径之间的依赖关系分析需要处理复杂的数据结构
- 需要区分路径依赖和 Watcher 依赖

**解决方案**：
- 使用路径前缀匹配分析依赖关系
- 分别构建路径依赖图和 Watcher 依赖图
- 使用 Map 和 Set 优化性能

**经验教训**：
- 数据结构设计很重要
- 算法选择影响性能
- 需要处理边界情况

### 4. 测试用例的异步问题

**挑战**：
- 测试用例需要等待异步更新完成
- 需要处理批量更新的时序问题

**解决方案**：
- 使用 `setTimeout` 等待异步更新
- 在测试中明确等待时间
- 使用 Promise 处理异步操作

**经验教训**：
- 异步测试需要仔细处理
- 时序问题需要明确处理
- 测试稳定性很重要
