# ECS 循环引用问题分析

## 问题描述

```
[Scene] Found possible circular reference in "pack:///chunks/ae/ae4eca4337e62da6b4bae17f5766d6fb11404607.js", 
happened when use "component" imported from "db://bl-framework/ecs"
```

## 问题分析

### 导入链分析

1. **packages/ecs/src/index.ts**
   ```typescript
   export * from './core';      // 导出 core 模块
   export * from './decorators'; // 导出 decorators 模块
   ```

2. **packages/ecs/src/core/index.ts**
   ```typescript
   export { ComponentManager } from './ComponentManager';
   ```

3. **packages/ecs/src/core/ComponentManager.ts**
   ```typescript
   import { getComponentMetadata } from '../decorators/component';
   ```

4. **packages/ecs/src/decorators/index.ts**
   ```typescript
   export { component, getComponentMetadata } from './component';
   ```

### 循环依赖链

```
index.ts
  ├─> core/index.ts
  │     └─> ComponentManager.ts
  │           └─> decorators/component.ts
  │                 └─> decorators/index.ts
  │                       └─> (回到 index.ts) ❌
  └─> decorators/index.ts
        └─> (回到 index.ts) ❌
```

### 问题根源

使用 `export *` 时，如果模块之间存在循环依赖，会导致：
1. 模块加载顺序问题
2. 导出符号未定义
3. 运行时循环引用错误

## 解决方案

### 方案 1: 延迟导入（推荐）

将 `getComponentMetadata` 的导入改为延迟导入（lazy import），只在需要时导入。

### 方案 2: 重构依赖关系

将 `getComponentMetadata` 移到 core 模块中，或者创建一个独立的 utils 模块。

### 方案 3: 改变导出方式

不使用 `export *`，而是明确列出需要导出的符号。

## 推荐方案

**方案 1: 延迟导入** - 最小改动，不影响现有 API
