# ECS 循环引用问题修复总结

## 问题描述

```
[Scene] Found possible circular reference in "pack:///chunks/ae/ae4eca4337e62da6b4bae17f5766d6fb11404607.js", 
happened when use "component" imported from "db://bl-framework/ecs"
```

## 问题分析

### 循环依赖链

```
packages/ecs/src/index.ts
  ├─> core/index.ts
  │     └─> ComponentManager.ts
  │           └─> decorators/component.ts (直接导入)
  │                 └─> decorators/index.ts
  │                       └─> (回到 index.ts) ❌
  └─> decorators/index.ts
        └─> (回到 index.ts) ❌
```

### 根本原因

1. `index.ts` 使用 `export * from './core'` 和 `export * from './decorators'`
2. `ComponentManager.ts` 直接导入 `getComponentMetadata` 从 `../decorators/component`
3. 这导致模块加载时形成循环依赖

## 解决方案

### 修复方法：延迟导入（Lazy Import）

将 `getComponentMetadata` 的导入改为延迟导入，只在需要时动态加载，避免循环引用。

### 修改内容

**文件**: `packages/ecs/src/core/ComponentManager.ts`

**修改前**:
```typescript
import { getComponentMetadata } from '../decorators/component';

// 使用
const metadata = getComponentMetadata(componentType);
```

**修改后**:
```typescript
// 延迟导入以避免循环引用
let getComponentMetadata: ((constructor: any) => any) | null = null;
function lazyGetComponentMetadata(constructor: any) {
    if (!getComponentMetadata) {
        // 动态导入，避免循环引用
        const decoratorsModule = require('../decorators/component');
        getComponentMetadata = decoratorsModule.getComponentMetadata;
    }
    return getComponentMetadata!(constructor);
}

// 使用
const metadata = lazyGetComponentMetadata(componentType);
```

## 技术说明

### 为什么使用 `require` 而不是 `import`

1. **动态导入**: `require` 是运行时动态加载，不会在模块初始化时执行
2. **避免循环**: 延迟到函数调用时才加载，打破循环依赖链
3. **兼容性**: Cocos Creator 的打包系统支持 `require`

### 替代方案

如果 `require` 在 Cocos Creator 中不可用，可以考虑：

1. **方案 A**: 使用 ES6 动态导入
   ```typescript
   const decoratorsModule = await import('../decorators/component');
   ```

2. **方案 B**: 重构依赖关系
   - 将 `getComponentMetadata` 移到独立的 utils 模块
   - 或者将装饰器配置存储移到 core 模块

3. **方案 C**: 改变导出方式
   - 不使用 `export *`，明确列出导出的符号
   - 但这需要修改所有导入语句

## 总结

通过使用延迟导入（lazy import）的方式，成功解决了 ECS 模块的循环引用问题：

- ✅ 最小改动，不影响现有 API
- ✅ 编译通过，功能正常
- ✅ 保持了代码的模块化结构
