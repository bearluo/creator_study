# Core 与 Creator 架构剥离详细计划

## 1. 项目概述

### 1.1 目标
将 bl-framework 的核心功能与 Cocos Creator 特定实现分离，使框架能够适配不同的游戏引擎（Unity、Unreal Engine、Phaser 等）。

### 1.2 业务价值
- **多引擎支持**：框架可以在不同游戏引擎中使用
- **代码复用**：核心逻辑只需维护一份
- **降低耦合**：核心功能与引擎实现解耦
- **易于扩展**：新引擎接入成本降低

### 1.3 复杂度评估
**Level 4 - Complex System（架构级重构）**

## 3. 目标架构设计

### 3.1 架构原则

1. **分离关注点**：核心逻辑与引擎实现分离
2. **依赖倒置**：核心模块依赖抽象接口，不依赖具体实现
3. **适配器模式**：使用适配器模式连接核心与引擎
4. **向后兼容**：保持现有 Creator 项目正常工作
5. **渐进式迁移**：支持逐步迁移，不要求一次性重构

### 3.2 目标架构图

```
┌─────────────────────────────────────────────────────────┐
│                    bl-framework Core                     │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐             │
│  │   ECS     │  │Behavior  │  │  Core    │             │
│  │ Framework │  │  Tree    │  │ Utils    │             │
│  └──────────┘  └──────────┘  └──────────┘             │
└─────────────────────────────────────────────────────────┘
                         │
                         │ 依赖抽象接口
                         ▼
┌─────────────────────────────────────────────────────────┐
│              Engine Abstraction Layer                    │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐             │
│  │  IEngine │  │ IResource │  │   IUI    │             │
│  │ Interface│  │ Interface │  │Interface │             │
│  └──────────┘  └──────────┘  └──────────┘             │
└─────────────────────────────────────────────────────────┘
         │                    │                    │
         │                    │                    │
    ┌────┴────┐          ┌────┴────┐          ┌────┴────┐
    │ Creator │          │ Unity   │          │ Unreal  │
    │Adapter  │          │Adapter  │          │Adapter  │
    └─────────┘          └─────────┘          └─────────┘
```

### 3.3 核心抽象接口设计

#### 3.3.1 IEngine 接口
```typescript
interface IEngine {
    // 资源管理
    resource: IResourceManager;
    // UI 管理
    ui: IUIManager;
    // 场景管理
    scene: ISceneManager;
    // 音频管理
    audio: IAudioManager;
    // 网络管理
    network: INetworkManager;
    // 热更新
    hotupdate: IHotupdateManager;
}
```

#### 3.3.2 IResourceManager 接口
```typescript
interface IResourceManager {
    loadAsset(path: string): Promise<IAsset>;
    loadBundle(name: string): Promise<IBundle>;
    releaseAsset(asset: IAsset): void;
    // ... 其他资源管理方法
}
```

#### 3.3.3 IUIManager 接口
```typescript
interface IUIManager {
    createNode(name: string): INode;
    createComponent<T>(type: string): T;
    // ... 其他 UI 管理方法
}
```

#### 3.3.4 其他接口
- `ISceneManager` - 场景管理接口
- `IAudioManager` - 音频管理接口
- `INetworkManager` - 网络管理接口
- `IHotupdateManager` - 热更新接口

## 6. 风险评估和缓解措施

### 6.1 技术风险

#### 风险 1: 抽象层设计不当
- **概率**: 中
- **影响**: 高
- **缓解措施**:
  - 充分调研不同引擎的 API 差异
  - 设计阶段进行多轮评审
  - 先实现 Creator 适配器验证设计

#### 风险 2: 性能开销
- **概率**: 中
- **影响**: 中
- **缓解措施**:
  - 适配器层尽量薄
  - 避免不必要的抽象
  - 性能测试和优化

#### 风险 3: 向后兼容性破坏
- **概率**: 中
- **影响**: 高
- **缓解措施**:
  - 保持现有 API 不变
  - 提供兼容层
  - 充分的兼容性测试

### 6.2 项目风险

#### 风险 4: 时间估算不足
- **概率**: 高
- **影响**: 中
- **缓解措施**:
  - 分阶段实施
  - 每个阶段设置里程碑
  - 预留缓冲时间

#### 风险 5: 资源不足
- **概率**: 低
- **影响**: 高
- **缓解措施**:
  - 优先实现核心功能
  - 非关键功能可延后
  - 寻求外部支持

### 6.3 业务风险

#### 风险 6: 现有项目迁移困难
- **概率**: 中
- **影响**: 高
- **缓解措施**:
  - 提供详细的迁移指南
  - 提供迁移工具
  - 提供技术支持
